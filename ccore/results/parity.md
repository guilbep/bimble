# Runtime parity: Rust egui app vs C core + Vue lab (ticket PAR2)

Generated by `node ccore/tools/parity.mjs --write`. Do not edit by hand.

**What this report supports.** The C core serves the same action names as the Rust app; for each action, its `enabled` and `pressed` flags are equal in the scenarios listed below (synthetic fixtures, mainly `golden/frame.json`, 72 elements); a query's answer has the same JSON key names and value types (its shape); the Rust shortcuts have a row in the lab's key table.

**What it does not support.** That an action does the same thing on both sides (only its flags are compared); that a query returns the same values (only its shape is compared); that a shortcut reaches the page (in a browser tab the browser keeps Ctrl N); parity with the v0.19.0 release: the committed Rust answers were dumped from a development build that reports `bimble 0.18.1` (`ccore/golden/parity/meta.json`).

- C core and Vue lab measured at commit `a43fb33` (the working tree at that commit). Run the tool again after a change of the actions, queries or the lab.
- Rust reference: `bimble 0.18.1` (a development build before v0.19.0, not the release binary), goldens `ccore/golden/parity/` made by `parity.mjs --rust` at commit `e76375d` (the headless native twin, ADR 0066: the real `Viewer::call`, no window).
- Scenarios (13): `empty`, `new`, `frame`, `frame_plan`, `frame_selected`, `frame_selected_plan`, `frame_sheet`, `ifc_readonly`, `placing`, `measuring`, `section_box_on`, `dirty`, `after_undo`. How each one is reached, per side: `steps.txt` (Rust: `golden/parity/<scenario>/`, C: `out/parity/c/<scenario>/`).
- Vue sources parsed: 95 files under `web-ui/src` (grep-level; see "Not resolved" at the end).
- A query counts as known in C when the C host answered it in some scenario (anything but "unknown query"), or its dispatchers name it (ticket TEST1: asked, not grepped).
- Gap (TEST1): no scenario hides anything, so `unhide`, `clear_temporary` and `show_all_in_view` are never enabled on either side and their enabled state is not compared. A scenario that hides an element (Rust goldens: on the branch `oracle/rust`, `parity.mjs --rust`) is still to add.

## 3D speed features of the Rust app

What Rust v0.19.0's renderer did to draw large models fast (ADR 0034-0036) and whether the C lab's viewport does it (ticket 3D1, ADR 0078; numbers in `ccore/results/frames.md`). The list is `THREED_SPEED` in this tool.

| Feature | Rust | C lab | Where / why not |
|---|---|---|---|
| Box tree for picks | `bimble-geom bvh.rs, pick_hit_bvh` | ported | ccore/src/bvh.{h,c} (3D2, Rust's queries_match_brute_force in test/bvh_test.c): the measure tool's ray in the core goes through it; the page's pick keeps its linear box scan (frames.md: under 3 ms on every model measured), no tree served to it |
| Copies as instances | `bimble-geom dedup.rs, instanced draws` | ported | dedup in ccore/src/scene.c; BMSH version 3 (ccore/src/scene_bmsh.h) sends each shape once; glviewport.ts draws shapes of 4 copies or more instanced |

| Moving budget | `next_moving_px, moving_fps, DrawOptions::min_radius` | ported | ported with a change (ADR 0078): a triangle budget from moving_fps, largest on screen first, far cells as proxies (3D2), unfinished leaves as proxies or box outlines, completed in slices after the stop |
| HLOD proxies | `bimble-geom hlod.rs, bimble-render proxies.rs` | ported | ccore/src/hlod.{h,c} (Rust's three tests in test/hlod_test.c), built in steps and served as BPRX (GET /mesh?proxies=N, wasm host_proxies); web-ui/src/gl/proxies.ts cuts the tree at 3 px moving, 1 px still (Rust: still frames exact); the setting moving_proxies turns them off |

| Screen edges while moving | `edges.wgsl, DrawOptions::screen_edges (ADR 0036 #6)` | **not ported** | not ported: a moving frame draws the edges of what its budget draws; frames.md measures the still frame without its edge pass |
