# Audit of the C port, 26 November 2026

Three independent reviews of the work merged on 25 and 26 November, each by an agent that had not
built the code. This file keeps their findings and what was done about each. The fixes are the
tickets FIXLIB, FIXDOC, FIXUI and FIXSES on the branch `next`.

Severity is the reviewer's. "Reproduced" means the reviewer ran it; "by reading" means it did not.

## A. Library layers and file readers

Scope: `ccore/src` readers (`.bimble` text and binary, `.bimbleview`, DXF, PDF, STEP), canonical
output, three functions compared with Rust line by line. Not covered: the history store
(`repo.c`, `repo_write.c`), `strtod.c` and `fmt.c` internals, the PDF content-stream interpreter,
verb validation, IFC export of a rotated placement, and every section of `DEVIATIONS.md` but 14.

Found sound: about 4.6 million mutated inputs through six readers under ASan and UBSan with leak
detection, no report. Merge `pick` and `merge_value`, plan `is_cut`, DXF `bulged` and `arc`: the
same logic as Rust. No `-0.0` survives a save.

| # | Severity | Finding | Evidence | State |
|---|---|---|---|---|
| A1 | high | A binary `.bimble` passes the memory budget: an array count is checked against the bytes left only, then allocated at once. | Reproduced: a 19,477-byte file, 1,243 MB peak, then an error. | Fixed (FIXLIB 1): one budget for both forms, 2^24 values and 1 GiB. 23 MB peak on that file. |
| A2 | high | On wasm32 the same size wraps to a small allocation. | By reading. The fix's test then showed `memory access out of bounds` on the old code. | Fixed (FIXLIB 1): `arena_alloc_n`, a checked multiply at every count read from a file. |
| A3 | medium | DXF budgets do not bound work: an ARC with a huge sweep makes up to 1,999,999 points. | Reproduced: a 4,236-byte file ran over 250 s. | Fixed (FIXLIB 2): 0.02 s. More than two turns is one turn; 4,000,000 points made at most. |
| A4 | medium | PDF dictionary insert is quadratic. | Reproduced: 100,000 keys, 12.5 s. | Fixed (FIXLIB 3): 0.01 s. |
| A5 | medium | STEP: an unterminated comment is scanned once per later statement. Rust does the same. | Reproduced: 1.03 MB, 22.2 s. | Fixed (FIXLIB 4): 0.01 s, same answer. |
| A6 | medium | Three bounds checks on file data have no test (mesh index, edge vertex index, element shape index). | Mutation: each check removed, every suite passes, also under the sanitizers. | Fixed (FIXLIB 5): a hostile fixture each. |
| A7 | low | Six more validation checks with no test; three checks caught only by a crash, a hang or the sanitizer. | Mutation. | Fixed (FIXLIB 5). |
| A8 | low | `DEVIATIONS.md`: numbers out of order, 16 twice, no 20; section 14 overstates the DXF budgets. | Reading. | Fixed (FIXLIB 6). |

Open after the fixes: the text reader's scratch buffer can peak at about twice its largest
container; filling the DXF point cap with arcs takes about 4 s (each sine costs about 2 µs).

## B. Local host program, session logic, release and CI

Scope: request handling against the documented rules, enable rules, unsaved and undo state,
session log replay, branch switch and merge, cache lifetimes, the platform files, the release
and the workflows. Not covered: any run on Windows, concurrent writers of `settings.json`,
32 connections under load, a mutation sweep of the session rules.

Found sound: every route checks the token, Host and Origin before routing; size limits apply
before a body is read; path tricks are refused; an action reported as off is refused by the core;
the session log replays only apply, undo, redo and state; cache keys follow the model revision.
Ten host and session suites under ASan and UBSan: no report.

| # | Severity | Finding | Evidence | State |
|---|---|---|---|---|

The changed-file case by reading. | Fixed (FIXSES 1): resolved paths compared; a session file with changes not saved is set aside as `<session>.orphan-<time>`, never overwritten; `query state` reports it. |
| B2 | high | Branch switch and merge drop link changes not saved. | Reproduced. | Fixed (FIXSES 2): refused, unless `discard` on a switch. |
| B3 | high | HEAD moves before the working file is written; a failed write leaves HEAD on the new branch. | Reproduced with a read-only folder. | Fixed (FIXSES 3): HEAD is put back. |
| B4 | medium | Export or share of an untitled model without a path writes `Untitled.ifc` into the host's working folder; the open-file guard compares text. | Reproduced. | Fixed (FIXSES 4). |

Open after the fixes: `/stage` holds a body twice (up to about 512 MB for one 256 MB drop);
`sheet_pdf`, `view_pdf` and `sheets_pdf` are queries that write a file; the brew formula is not on
`main`; long paths, `ReplaceFileW` and reproducible archives on Windows; none of the Windows path
code has run on Windows. Found by the fix ticket: the history stores no `links` section, so a
clean switch or merge rewrites the working file without links already saved; a session set aside
cannot be restored from the page, and the page does not show that one exists.

## What the audit did not look at

The history store's readers, number parsing and formatting internals, the PDF content-stream
interpreter, IFC export beyond the goldens, any Windows or macOS run, the wasm build under a
sanitizer. Nothing in this file says those are sound.
