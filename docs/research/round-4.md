## Wave A

### UX1 — The lab shell as an explicit state machine

**Goal and reason.** Pierre: one can be **stuck on the Home page**; the paths of the UX flow are
broken, and he wants a graph that represents the state. The name for it is a **statechart**
(Harel): a finite set of named states and a table of transitions. Today the shell's state is
spread over `W/App.vue`, `W/shell/tabs.ts`, `W/bimble.ts` (`tabCall` `:966`, `openView` `:974`,
`state` `:225`) and each component navigates by itself.

**Do, in this order.**
1. **Reproduce first, change nothing.** `C/test/lab_shell.mjs` walks every path and prints a
   table of dead ends, on the native host and in wasm: nothing open → new / open / import /
   recent; open failed (bad file); model closed; the view-only build; native without a path;
   wasm picker cancelled; back from each page; the last tab closed; page reload with a live
   native session; a page opened with no model. Commit this list in the report: it is the proof
   the fix is aimed at the real faults.
2. **One module**, `W/shell/machine.ts`: plain typed TypeScript, no library (add none). States:
   `home`, `opening`, `model.view`, `model.page(name)`, `model.sheet`, `error(message)`,
   `closing(unsaved)`, `viewOnly.*` as the build needs. Events: `NEW`, `OPEN`, `IMPORT`,
   `OPENED`, `FAILED`, `CANCELLED`, `SHOW_PAGE`, `SHOW_VIEW`, `BACK`, `CLOSE`, `DISCARD`, `KEEP`,
   `HOME`. A `const TRANSITIONS` table; `send(event)` is the only way to move; an event with no
   row in the current state is logged once and reported by the tests, never silently dropped.
3. **Derive, do not duplicate.** Shell state is page state, not model state. What the C session
   knows (`query state`: `open`, `tab_open`, `editable`, `unsaved`, `file`) is **read**, never
   copied: `model.*` is only reachable while `state.open` is true, and a guard on every `rev`
   change sends `CLOSE` if the session says no model is open. Write the mapping as a table in
   the module's header comment.
4. Every component navigates through `send`: `App.vue`, `TabsBar.vue`, `ViewTabs.vue`,
   `Navigator.vue`, `FileMenu.vue`, `Home.vue`, `QuickBar.vue`, the pages' back links. Grep
   proves no other writer of the old state remains.
5. A control is shown only in a state where its event has a row.

**Owns.** `W/shell/machine.ts` (new), `W/shell/machine.test.mjs` or `C/test/shell_graph.mjs`
(new), `C/test/lab_shell.mjs` (new), `W/App.vue`, `W/shell/tabs.ts`, `TabsBar.vue`,
`W/pages/Home.vue`, one row pair in `ports.mjs`. **Hooks.** `W/bimble.ts` (the shell state leaves

**Do not touch.** `C/session/*.c` (report a missing fact of `query state`; do not add one),
`W/ccore.ts` (FS1), `W/glviewport.ts` (G2).

**Read first.** `W/App.vue`, `W/shell/tabs.ts`, `W/bimble.ts:225,966-974`, `W/pages/Home.vue`,
`W/dialogs/FileMenu.vue`, `C/session/calls.c:521` (`query state`), `:1166-1179` (new, open,

### FS1 — Open, import, link and save-as from the desktop UI

**Goal and reason.** On the released desktop build a model can only be given on the command
line: `open` answers "the C core has no file dialog" (`calls.c:1167`), `nativeClient.action`
sends no body (`W/bimble.ts:303`), and only the wasm lab has pickers (`W/ccore.ts:278-296`).
This is gap 1 for daily use.

**Do.**
- **A file browser dialog in the page**, served by host queries: `query fs_list {dir}` (entries
  from `cc_platform.list_dir`, H1), `query fs_home`, filter by extension per action (`.bimble`,
  `.ifc`, `.bimbleview`, `.pdf`, `.dxf`). **The path rule (state it in the header and test it):**
  the host lists and opens only under the user's home directory and the roots given at start
  (`--root <dir>`, repeatable; the directory of the model on the command line is one); a path is
  resolved (`realpath`) before the check; a link that leaves the roots is refused; hidden entries
  are not listed. Files are untrusted input: budgets on entries per directory and on name length.
- `open`, `import_ifc`, `link_model`, `link_pdf`, `link_dxf`, `save_as` take the picked path;
  `nativeClient.action` sends the body. An untitled model's Save goes to Save as.
- **Recent files**: Rust's rule and count (`V/settings.rs:30,38,167`, `V/home.rs:55`; 12
  entries). Store them where SET1 will: the settings file. If SET1 is not merged, write
  `recent_files` only, in Rust's schema, so SET1 adopts the file. `recent_files` leaves the stub
  list (`calls.c:977`); Home lists them and opens one.
- **Drag and drop** of a file onto the page (`V/lib.rs:4765`): wasm takes the bytes; native takes
  the dropped file's bytes through the same staging route the wasm pickers use (`host_open`
  flags), since a browser gives no path.
- **Unsaved-changes guard**: every path that drops a model (`calls.c:1168` refuses without
  `discard`), and the page's `beforeunload`.

**Owns.** `C/host/fs.c/.h` (new), `W/dialogs/FileBrowser.vue` (new), `W/ccore.ts`,
