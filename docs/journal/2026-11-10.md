## Convert every element; a binary `.bimble` (ADR 0042)
- Asked (Pierre): the 9 models that couldn't convert should convert too ("ok do it!"), and "no json!?
  bson? protobuf? sqlite? what do we do?".
- Done: every product with a body converts. Classes not edited by dimensions become
  `IfcBuildingElementProxy` keeping their own class (`ifc_entity`, shown everywhere), exported with
  it in ObjectType (writing IFCDOOR with a proxy's attributes would be invalid) and read back from
  it. Meshes are stored relative to their own first point, not the survey origin (≈ 2.5·10⁹ mm in
  every vertex). File → "Convert to .bimble (editable)…".
- `.bimble` v2: `bimble\0` + gzip of CBOR (one new dependency, ciborium); JSON v1 still read, and
  any save to a `.json` path writes it. Decompressed size capped. BSON, protobuf, postcard/bincode and
  SQLite set aside (ADR 0042: no gain, no tagged enums, or a C dependency and no canonical bytes).
- Shapes once: mapped copies (moved and turned only) share one mesh in memory, in the file (a table
  ahead of the model) and in the scene (instances). `canonical()` sent the whole model through a JSON
  value, which broke the sharing and cost most of the open time: `canonical_model` fixes meshes in
  place.
- Numbers (17 private models, sizes only; table in ADR 0042): all 17 convert (8 before); the binary file is 5.5–46× smaller than the IFC. The
  395 MB sprinkler model: 4.2 GB as JSON, 398 MB binary, 20 MB with shapes once; opens in 3.8 s and
  1.2 GB (JSON: 40.6 s and 13.6 GB); converts in 7.8 s, 2.1 GB (124 s, 9.0 GB). The 832 MB model:
  52 MB, opens in 2.8 s.
- Tests: proxies keep their class through export and import (fails on the old code: no importable
  elements); the binary file is exact and canonical, copies share again after reading, a cut-off
  file is an error; shared meshes become placed instances in the right place.
- Not done: 416 772 property values of one model are of kinds not imported (unchanged).

## Issue #59: panic on zoom on GL and WebGL2 (screen edges)
- Reported from the office: the IFC opens, the first zoom freezes with "wgpu error: Validation Error
  ... 'bimble screen edges' ... WGSL textureLoad from depth textures is not supported in GLSL", in
  the browser (WebGL2) and the installed Linux build (wgpu's GL backend).
- Cause: the screen-edges shader (ADR 0036 #6) read the depth with `textureLoad` on a
  `texture_depth_2d`, which naga cannot write in GLSL. The pipeline is built for the moving view on
  slow machines, hence at the first move.
- Fix: the shader reads the depth as an unfilterable float texture through a nearest sampler
  (`textureSampleLevel`): GLSL can write it, and the nearest sampler keeps a depth texture complete
  in GL ES (with GL's default filters, a read would give 0, so no edges). Screen edges stay on GL.
  Same pixels on Metal (2349 of 2380 line pixels found, 2439 of 2439 screen edges near a line,
  before and after). Other GL paths checked: GPU occlusion queries already native only, GPU culling
  only with storage buffers (not WebGL2), its compute shader translates to GLSL ES 3.1.
- Test: every entry point of the three shaders translates to GLSL (ES 3.0 WebGL, ES 3.1 for the
  compute), as wgpu does on GL; it failed on the old shader with the reported message. naga added
  as a dev-dependency (already in the tree through wgpu). Not tried in a real browser or on Linux GL.
- Decided by: Pierre asked; Claude (fix the shader rather than drop screen edges on GL).
