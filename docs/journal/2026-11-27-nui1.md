# 27 Nov 2026 — ticket NUI1: `bimble`, the native Linux app, from spike to the integration branch

Branch `cc/nui1` from `next`. Decided by Pierre: "I think you need to work on a native ui based on our
core/rendering engine. reuse the full web-ui ux for now"; the choices delegated ("performance is
everything"), recorded in ADR 0084. Numbers below are offscreen on the dev machine (Apple M1 Pro,
Asahi, Mesa Vulkan), 1-minute load 6.9–9.0 (other agents working).

## What happened

- **Brought over** from `spike/native-app` (NAT2's prototype I): the renderer, the ImGui shell, the
  export of the lab's data. Not brought: prototype H, the page's `?nativeview` flag, the NAT1 viewer.
- **The renderer draws parts** (the open model, each link, a link's proxies), uploaded on loader
  threads. The spike made one scene of every link, one after the other, and kept the session's copy of
  each beside the renderer's; now a link's cache is decoded by the loader from its mesh blocks, batch
  by batch under the session's read lock, and freed after its upload. 17 synthetic links (8,024
  elements, 3.93 M triangles), the orbit-zoom preset: first picture 69–93 ms, complete 408–491 ms, peak
  85 MB (the spike: 47 ms, 556 ms, 334 MB); input → frame 7.3–7.7 ms median, 15–19 ms max; under ASan
  and UBSan the same run is clean (first 168 ms, complete 932 ms, peak 455 MB).
- **The program**: Home, the File menu, the file dialog (`fs_list`), the Links panel, Properties with
  property sets, Settings, the Performance report (the lab's shape), the view cube, plans and sections
  (orthographic, clipped), the right-click menu, FR / EN, six themes; every other control says "not yet
  (native)" and File › Open in the web lab starts `bimble-ccore open`.
- **Build, release, CI**: `ccore/build.sh native-app` (5.0 MB, SDL3 and FreeType from the system), the
  Linux archive gains `bimble`, the job `ccore-native` on lavapipe (not required), `ccore/ci/run.sh
  native`, `test/native_app_test.mjs` (25 checks), the shell machine ported to C and checked against
  `machine.ts` row by row (`test/native_machine_test.mjs`, 91 rows × 3 sessions).
- **The edit loop** (`make dev-native`): save a shell C file → tcc 67–110 ms → offscreen shot 188–258 ms.
- **A bug the screenshots found**: Properties printed numbers from the JSON token, which points into the
  answer's buffer, freed after the parse (a "?" for the slab's thickness): now from the value.
- **The owner's project: not measured.** The run (a private cache folder, a 6 GB cap, the measure lock
  taken non-blocking only for the run, memory waited for outside it) found the machine's measurement lock
  held by other tickets' runs for its whole 30-minute window, and gave up as agreed with the orchestrator.
- **Also found**: the measure tool across links works natively (two links' slabs 30 000 mm apart, the
  pointer call 15–64 ms while a link is decoded for it); the screenshots against the lab's moved
  Properties under the navigator, the language switch and Performance into the status bar.
